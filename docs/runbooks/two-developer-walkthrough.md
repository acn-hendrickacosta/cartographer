# Two-developer walkthrough: central topology

This runbook walks through the full Phase 2 happy path: two developers on separate machines sharing a central Cartographer index. When this runbook passes end-to-end, Phase 2 exit criteria 1–10 are satisfied.

**Prerequisites:** A project already in version control. Both developers have Cartographer installed (`pipx install "cartographer[embeddings,mcp]"`).

---

## Infrastructure setup (one-time, done by admin)

The admin provisions two backend instances. The simplest local setup uses Docker Compose:

```bash
# Start pgvector and Neo4j
docker compose -f docs/ci/docker-compose-central.yml up -d
```

Or use managed services:

| Backend | Managed option |
|---|---|
| pgvector | Neon, Supabase, RDS with pgvector extension |
| Neo4j | Neo4j Aura (free tier works for testing) |

Issue two sets of database credentials: one for Dev A, one for Dev B. They share the same database instances but use separate DB users so activity can be attributed.

---

## Dev A: project owner

### Step 1 — Initialize with central topology

From the project root:

```bash
cartographer init --topology central
```

This writes `cartographer.toml` with `topology.mode = "central"` and generates a promotion token in `.cartographer.local.toml`. Commit `cartographer.toml`; never commit `.cartographer.local.toml`.

### Step 2 — Configure central backend credentials

Edit `.cartographer.local.toml` (already gitignored):

```toml
[central_vdb]
host = "your-pg-host"
port = 5432
user = "dev_a"
password = "..."
database = "cartographer"

[central_kg]
uri = "bolt://your-neo4j-host:7687"
user = "dev_a"
password = "..."

promotion_token = "<generated by cartographer init>"
```

### Step 3 — Verify connectivity

```bash
cartographer doctor
```

Expected output: all checks pass, including `[central vdb] reachable` and `[central kg] reachable`.

### Step 4 — Seed and work

```bash
cartographer seed .
```

Open a Claude Code session. Work on the project. The local index populates as you work.

### Step 5 — Promote to global after merging

After a branch merges to main:

```bash
cartographer promote
```

Expected output:
```
cartographer promote
  project:  <your-project-id>
  mode:     full
  chunks:   <N> 
  nodes:    <M>
  edges:    <P>
  promoted: <N> chunks, <M> nodes, <P> edges
promote complete
```

**Exit criterion 2:** `cartographer promote` runs without error and writes to global scope.

**Verify idempotency** — run again immediately:

```bash
cartographer promote
```

The counts must be identical. **Exit criterion 3.**

## Dev B: second developer

### Step 1 — Clone the repo

```bash
git clone <repo-url>
cd <project>
```

### Step 2 — Initialize

```bash
cartographer init
```

Since `cartographer.toml` already has `topology.mode = "central"`, Dev B's init picks it up automatically and generates a new promotion token for their machine.

### Step 3 — Configure central backend credentials

Edit `.cartographer.local.toml` with Dev B's database credentials (same host/database, different user/password):

```toml
[central_vdb]
host = "your-pg-host"
port = 5432
user = "dev_b"
password = "..."
database = "cartographer"

[central_kg]
uri = "bolt://your-neo4j-host:7687"
user = "dev_b"
password = "..."

promotion_token = "<generated by cartographer init for dev B>"
```

### Step 4 — Verify

```bash
cartographer doctor
```

Expected: all checks pass. **Exit criterion 4, 10.**

### Step 5 — Seed locally

```bash
cartographer seed .
```

This indexes Dev B's local checkout.

### Step 6 — Start serve and open Claude Code

```bash
cartographer serve
```

Open Claude Code and ask a question about the code Dev A wrote. The preload context block should contain chunks and nodes tagged `origin: global` from Dev A's promoted work.

**Exit criterion 5:** preload context includes artifacts tagged `origin: global`.

### Step 7 — Verify local-first shadowing

Dev B locally edits a file Dev A promoted. Without promoting:

```bash
cartographer seed <modified-file>
```

Ask Claude about that file. Verify the local version is returned (not the promoted version Dev A wrote). **Exit criterion 7.**

## Incremental promotion

After the first full promote, subsequent promotes are incremental by default:

```bash
# Only promotes artifacts changed since last_promoted_at
cartographer promote

# Force full re-promote
cartographer promote --full
```

The incremental mode filters VDB chunks by `updated_at > last_promoted_at` and KG nodes by the corresponding changed paths.

## Tenant isolation check

To verify tenant isolation (**exit criterion 8**):

1. Create a second project with a different tenant: `cartographer init` in a separate directory and set `isolation.tenant = "team-b"` in `cartographer.toml`.
2. Seed and promote that project.
3. In Dev A's session, run a `kg_query` with a node from team-b's project. Confirm the query returns no results (tenant boundaries are enforced at the index level by project_id partitioning).

---

## Scope write protection check

To verify scope write protection (**exit criterion 9**):

The `_check_scope_write` helper in both MCP servers will return `SCOPE_WRITE_FORBIDDEN` for any global-scope write attempted without a valid promotion token. Current MCP tools are read-only, so the guard is in place for future write tools.

To manually verify the gate in `promote.py`: remove the `promotion_token` from `.cartographer.local.toml` and run `cartographer promote`. Expected output:

```
promotion_token not set in .cartographer.local.toml
```

The command exits before writing anything.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `doctor` fails on VDB check | Wrong pgvector host/port/password | Check `.cartographer.local.toml [central_vdb]` |
| `doctor` fails on KG check | Neo4j not running or wrong bolt URI | Verify Neo4j is up and bolt port is open |
| `promote` reports 0 chunks | No local index — seed hasn't run | Run `cartographer seed .` first |
| `promote --incremental` skips everything | `last_promoted_at` is in the future | Delete `~/.cartographer/registry.json` entry and re-run `cartographer init` |
| Global chunks not visible in Dev B session | Forgot to start `cartographer serve` | Run `cartographer serve` |
